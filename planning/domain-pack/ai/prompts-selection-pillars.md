# 三支柱判断标准（并入 prefilter / selection-score）

> 部署时：负类清单并入 `prompts/prefilter.md`，支柱判据与动作层要求并入 `prompts/selection-score.md`。本文件是 pack 内的评审载体。
> 首批 gold 依据：A0 专家批注（12 条：2 正 / 10 负，见 gold-selection-seed.jsonl）。

## 一票否决负类（宽预筛直接拦，不进评分）

以下内容**即使写得再好也不进精选**（与 agent 使用无 immediate 关系）：

1. 公司经营/融资/IPO/并购/人事（如"Anthropic 招股书披露收入 12 倍"）
2. 监管/诉讼/听证/政策未落地讨论（如"澳参议院传唤 CEO"）
3. 安全事件与对齐八卦——**除非**直接改变某个 agent/模型的使用决策（如"某 harness 因漏洞应立即升级"）
4. 行业格局评论/市占率/算力采购传闻（如"传北京拟批准芯片采购"）
5. 非工具向研究论文（基准污染审计、纯学术）
6. 企业内部流程案例（如"某公司 12000 名员工如何用模型"——除非含可复用的部署机制）

## 三支柱判据（进评分维度）

**P1 模型榜与模型动态** —— 判据：内容是否改变"该用哪档模型"或"该在哪跑"。
加分：能力跃迁/降价（含具体价格数字）/开源权重（可本地部署）/评测结论（附榜位变化）。示例（gold 正）：Sonnet 5.5 智能指数 56 仅低于旗舰 2 分；Holo4 开源系列发布。

**P2 项目周榜（agent-usage 过滤）** —— 判据：新工具/仓库是否让 agent 更好完成某类任务。
加分：官方出品（如 anthropics/financial-services 领域 skills 范式）/多 harness 支持/直接可装。减分：纯概念、无 README 质量、与 agent 工作流无关的 trending（哪怕全 star）。
角色分榜（category=pm / dev…）：同一判据 + 角色视角加权（PM→原型/需求/评测类工具；dev→CI/审查/部署类）。

**P3 harness 必装集合** —— 判据：是否值得进入某 harness 的"装/删"清单。
加分：免 key 可跑（如 paperjsx 本地生成文档）/解决高频痛点（gh-fix-ci）/官方维护。**必须同时评估 context 成本**：装它占多少上下文、和现有 skills 是否重叠——"该删什么"与"该装什么"同权。

## 动作层要求（写作与精选共用）

每条精选内容在摘要里必须落到三类动作之一，写不出动作的不精选：
- **换模型**：换成什么、干什么用、价差多少
- **装技能/插件**：装到哪个 harness、解决什么任务、注意（key/许可/context 成本）
- **迁算力**：迁到哪、省多少、迁移成本

## 评分倾向建议（对 selection-score.md 五维权重的修正方向）

- `及时性`：榜单/价格类内容时效权重调高（48h 内价值最大）
- `实用性`：以"动作可执行性"为核心分——有具体模型名/仓库名/安装命令 > 泛泛介绍
- 来源分级沿用 T1/T1_5/T2；厂商定价页与官方 changelog 视为 T1
- 噪声压制：上述六类负类 → 0 分；营销水文（"最强/颠覆/必学"无实体）→ 0 分
