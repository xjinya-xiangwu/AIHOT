## §1 产品定位

**产品 = 为某个专业领域提供「专家 × Agent 协同」所需的完整工作环境——同时是一个能通过不断采集信息、在与专家互动反馈中持续自我进化的环境。**

三个关键词：

- **完整**：情报、知识、工具、方法、偏好——专家开展工作所需上下文的全集。装入任意主流 agent（ZCode/Claude Code/Codex 等 7 端已验证）后，开箱即具备"配合了 1-2 年"的默契。**〔主张状态：待验证——默契体验尚无盲评证据，验证方法见 §2.3/§7 Phase A0〕**
- **协同**：专家贡献判断、品味、反馈；Agent 承担采集、沉淀、执行、分发
- **自我进化**：采集 → 沉淀入库 → 协同使用 → 专家反馈 → 更新环境 → 循环。**〔主张状态：待验证——闭环能否产生可感知收益由 Phase A0 先行检验，而非等基础设施建完〕**

**定位演进史**：v1 情报引擎中心 → v2 知识底座中心（库 > 流）→ v3 进化闭环中心（当前）。

**价值链（2026-09-30 修正，D12）**：L0 只采『对 agent 使用立即相关』的情报——新模型发布/降价/能力变化、新 harness 与 agent 工具、能更好完成某任务的新 skills/插件/MCP、新的便宜 tokens 中转站与算力平台；**剔除一切与 agent 使用无 immediate 关系的内容**。L0 内容沉淀为 **L1 技能包层的必要内容**（Agent 执行环境：skills / AGENTS.md / prompts / MCP 配置 / 模型推荐档位 / 成本参数）→ 用户实际使用沉淀为 **L2 知识底座**（哪些技能高频被用、哪些 prompt 被改、哪些模型被选、纠错与偏好）→ 反哺 **L3/L4 的产品设计**。资讯本身不是刚需——用户缺的不是信息，是『此刻该把 agent 换成什么、装什么、迁去哪』的决策。

**与相邻概念的差别**：

| 概念 | 缺什么 | 本产品 |
|---|---|---|
| 知识管理（文档库/wiki） | 无代谢：不主动采集，无反馈回路 | 有感知与进化的有机环境 |
| RAG 知识库 | 被动检索：等人喂料，不沉淀 | 主动采集 + 自动沉淀 + 反馈迭代 |
| 情报站（如 AIHOT 类） | 只输出流：48h 衰减，不复利 | 情报只是输入，必须沉淀为底座 |
| Agent 框架/harness | 只有骨架：无领域内容 | 骨架 + 领域血肉（底座/技能/判断标准） |

## §3 总体架构

- **L0 感知层**：**Agent 使用情报传感器**（AIHOT 实例窄化：新模型 / harness / skills·插件·MCP / 便宜算力中转；一般资讯剔除）· asp collector（技能生态周更抓源）· 个人输入（文档/对话/Lark/memory）——**所有输入先过 §4.0 数据准入矩阵**
- **L0→L1 内容更新管线**（机制而非独立层，§4.2）：相关性过滤（一票否决）→ 结构化抽取 → 去重合并 → git PR → 周期 compaction
- **L1 技能包层＝Agent 执行环境**（★首发可售，已有基础）：asp packs（base + 角色层）——skills / AGENTS.md / prompts / MCP 配置 / 模型推荐档位 / 成本参数，由 **L0 情报与 L2 使用反馈双轮更新**
- **L2 知识底座**（🔴GAP）：**由使用沉淀**（高频技能 / 被改 prompt / 模型选择 / 纠错偏好）+ 专家反馈 → 实体档案 · 事实时间线 · 领域 SOP · 案例库 · 术语表 · 立场偏好——**分私人层/工作层（见 §4.0）**
- **L3 协同层**：ZCode/Codex 会话 · 通用 skills · Agent-sync · memory · MCP 工具 · asp 分发
- **L4 进化层**（🔴GAP）：反馈三通道 → 周审 → 进化动作（改底座/迭代技能/调优传感器）——**行为变更须过 §4.3 发布回归门**

进化闭环（D12 修正）：L0 情报经管线沉淀为 **L1 包内容**（新技能入包 / 模型推荐档 / MCP 清单 / 成本参数）→ 用户实际使用产生反馈与使用数据 → **L2 沉淀**使用知识与专家纠错 → L4 经周审与回归门更新 L1 包与判断标准 → 反哺 L3/L4 产品设计。两大项目咬合点升级：asp 既是 **L1 载体**又是分发渠道，AIHOT 是 **L0 传感器**（内容范围见 D12）——未来商品经同一条 asp 渠道分发。

## §4 模块设计（v0 设计）

### §4.0 数据准入与流转矩阵（P0——先于 Phase A 一切入库工作）

**问题**：私人素材（健康信息、在职机构材料、无再分发权内容）与可发布/可售卖资产之间此前没有隔离规则。

**三层分区**：

| 层 | 位置 | 可否进 Lark 发布 | 可否进 pack/商品 | 可否进公开 git 远端 |
|---|---|---|---|---|
| 私人层 P | `kb/<domain>/private/` | ❌ | ❌ | ❌（仅本机 + Agent-sync 私有仓库） |
| 工作层 W | `kb/<domain>/` 其余 | ✅（周度同步） | 需发布门 | ✅（私有仓库） |
| 商品层 C | `packs/kb-seed-export/` 导出区 | — | ✅ | 视授权 |

**来源准入矩阵**：

| 来源 | 所有者/授权 | 默认层 | 晋升路径 | 禁止 | 保留/删除 |
|---|---|---|---|---|---|
| AIHOT 公开精选 | 公开网页；仅存链接+自写摘要 | W | →C：发布门 | 复制原文全文（尊重 site_fulltext=false 惯例） | 随 compaction |
| 家族 A/B 执行方案 | 自有 | P | 去敏提炼（剥离在职机构信息，沿用家族 B 合规红线）→W→C | 原文直出 | 原文永久 P |
| RMC 调研（含健康信息） | 私人敏感 | **P（仅）** | **无**（不晋升） | 进 timeline 共享区/Lark/pack/公开远端 | 用户主动删除时删 |
| 会话 memory 偏好 | 私人 | P（positions 私人区） | 通用化提炼→W→C：发布门 | 原始对话直出 | 随 memory 生命周期 |
| Lark 知识库 | 依各文档授权 | W（默认） | 逐文档确认授权→C | 自动批量进 C | 不动 Lark 侧 |
| 在职/前任雇主与客户材料 | 他人所有 | **禁止采集** | — | 一切目的地 | —（不入库） |

**发布门（human gate）**：W→C 与任何 Lark 同步前，人工过 checklist：①授权/再分发权确认 ②个人信息与机构信息去敏确认 ③来源与许可标注完整 ④勾选记录留档。发布门独立于周审，不可由 agent 自行通过。

**默认拒绝验证**：Phase A1 验收含一次渗透测试——植入含个人信息与模拟客户材料的样例，跑完整采集→沉淀→发布→pack 流程，断言全部被拦（任何一漏即修复后重测）。

### §4.1 L2 知识底座 v0（第一优先，但晚于 §4.0）

**载体**（已定）：git+markdown 为单一事实源；Lark 作人读发布面（单向、过发布门）。

**目录 schema**（在 v1.0 基础上增加 private/）：

```
kb/<domain>/
  INDEX.md          # 库导航（llms.txt 式），agent 检索入口；不含 private/ 内容
  glossary.md       # 术语表
  positions.md      # 通用判断/偏好（可商品化部分）；原始/敏感偏好存 private/
  entities/         # 实体档案（一实体一文件）
  timeline/         # 事实流水（按月归档）
  sops/             # 领域工作法（可编译为 skill）
  cases/            # 案例库
  private/          # 私人层（§4.0 P 区）：RMC 健康、原始 memory、敏感偏好
```

**事实条目模型（七字段，F-06）**：

```markdown
## 2026-09-15
- f012 | claim: 智谱发布 GLM-5.3，上下文 256K，价格下降 40%
  | src: AIHOT精选#1234 + URL（来源级别 T1官方/T2媒体/传闻）
  | pub: 2026-09-15（发布时间） | ver: 2026-09-16（核验时间；未核= null）
  | scope: 适用范围（如"截至 2026-Q4 中国大陆定价"）
  | status: active | sup: null（被取代/撤回时指向替代条目 id）
```

规则：①status ∈ active / pending（冲突待核）/ superseded / retracted；②来源级别 ≠ 事实可信度，凡快变域（产品价格、政策、临床）默认 90 天复核期，过期未核自动降 pending；③同一实体冲突条目**不自动合并**，标 pending 双链保留；④高风险主题（医疗/合规）条目仅人工可置 active，agent 引用时按 scope 与 status 决定**弃答或带限定作答**。

**SOP→skill 编译**：SOP 经 ≥3 次实战验证 → 提炼 SKILL.md → **过 §4.3 发布回归门** → 周审后进 asp packs 发版。缺陷回流为 SOP 修订。

**检索 v0**：INDEX.md 导航 + agent 文件检索；会话按需加载 positions.md（通用区）+ INDEX 定位。MCP 检索留 v1。

**冷启内容源**（全部按 §4.0 矩阵准入）：家族 A/B → 去敏提炼入 sops/；AIHOT taxonomy 的 ENTITIES/IDENTITY_LEXICON（MIT 开源）→ entities/ 与 glossary.md；RMC → **仅 private/**；memory → 通用化提炼经发布门入 positions 通用区。

**v0 验收（质量导向，F-05）**：①§4.0 默认拒绝测试通过；②首批 ≥10 实体 + ≥50 事实（全部七字段合规，pending 占比 <20%）+ ≥3 SOP；③盲评冒烟：新会话凭 INDEX+positions 回答三问（你是谁/怎么判断/领域里有什么）——**此为冒烟检查而非效果证明**（效果证明=Phase A0 盲评）；④一次周审流程走通并记录实际审阅耗时。

### §4.2 L0→L1 内容更新管线 v0（机制，非独立层）

**流程**：每日 job（AIHOT API 精选 + asp collector 候选）+ 事件触发 → **agent-usage 相关性过滤（一票否决：与 agent 使用无 immediate 关系的内容直接剔除，D12）** → 结构化抽取（实体/事实/术语三类，复用 structure.md 范式）→ 去重（实体+日期+语义；冲突→pending）→ **两类产出：①入包项**（新技能候选 / 模型推荐档位 / MCP 清单 / 成本参数 → asp 周更流水线）；**②入库项**（实体/事实 → 每日一个 git PR 进 L2，按实体分 commit）→ 人周审合并。

**审阅预算先行（F-05）**：上线前先跑 **1 周小样本**（~20 条资料），按来源级别记录实际审阅分钟数/条，得出周审阅预算；此后**摄入量受预算约束**——超预算时降低摄入/提高预筛门槛，而不是放宽审核或延后核实。

**compaction**：周度合并 timeline 冗余；月度综述草稿（复用 report-period 范式）→ 人审后入 cases/ 或更新 INDEX。**过期与冲突清理纳入 compaction 范围**（status 降级、sup 链维护），清理量与新增量同报。

**指标（F-05 修订）**：
- 阶段门（决定是否扩产）：任务可采纳率（盲评）、错引/过期引用率、反馈解决时间、实际审核耗时 vs 预算、单位可用事实成本
- 观察项（不设门槛，仅运营参考）：周 PR 数、facts 月增量、抽取量

**成本护栏**：复用 AIHOT 回执/熔断；抽取与写作模型分离。

**v0 验收**：连续 7 天自动 PR；实测审核耗时 ≤ 预算；抽检准确率 ≥80% 且错引率有基线记录。

### §4.3 L4 进化闭环 v0（定位核心，先行小闭环验证）

**反馈三通道**：①会话隐性反馈 harvesting（memory 纠错/偏好 → 周度聚类；**私人内容按 §4.0 留 P 区**）；②周审 PR（每周一次，审日报 PR + 聚类产出）；③gold 样本回流（人审错漏标入 gold → 触发 §4.3 回归门，而非只等季度）。

**发布回归门（F-07，新增）**：任何影响 agent 行为的变更（prompts/门槛/SOP/技能/positions 通用区规则）合入前必须：跑**相关 gold 切片 + 保留测试集（held-out，仅用于测试不参与调优）**→ 记录变更前后结果、批准人、可回滚版本号 → 通过才允许 asp 发版。季度 SelectBench 重校准的定位是**扩大评测覆盖**，不替代逐次发布门。

**进化动作清单**：改底座内容 · 改 SOP/技能 · 改 AIHOT prompts/信源/门槛 · asp 发版触达 7 端。

**指标（F-05 修订）**：阶段门 = 盲评可采纳率变化（变更后 ≥ 变更前，held-out 不回退）、错引/过期率下降、反馈从记录到入库的解决时间、回归门通过率；~~周均 PR≥3 / 月增 ≥100 facts / 技能月迭代~~ 降为观察项。修订记录：positions.md 通用区每次修订须在 git 历史可追溯（含触发反馈来源）。

**v0 验收**：一次完整最小闭环（Phase A0 定义）产生可盲评的前后差异；回归门在 ≥2 次真实变更上运行并留档。

### §4.4 L0 Domain Pack 规范 v0

**Pack 内容（边界修订，F-09）**：Domain Pack = **传感器 + 判断标准**，不含 kb-seed（kb-seed 是独立商品 M3）：

```
domain-pack/<domain>/
  industry/                 # AIHOT 实例整套定制
  gold-selection.jsonl      # 传感器校准样本（归属本 pack）
  AGENTS-domain.md          # 领域工作规范摘要
  manifest.json             # 版本/MCP 前缀/依赖（依赖 M3 时显式声明，可选组件）
```

gold 拆分：`gold-selection.jsonl`（M1 传感器精选校准）与 `gold-skill.jsonl`（M2 技能行为校准）分属不同商品，manifest 分别声明，不共用文件。

**"7 端生效"的定义与验证（F-09）**：≠ 分发脚本通过。逐端验证四项：安装成功、**上下文正确加载**（agent 实际读到 pack 内容）、工具权限正常、可回滚。asp 已有 16/16 安装级校验，运行级验证在 Phase D 逐端补测。

**AI 首发 pack 清单（D12 窄化）**：信源 20-40 全部为 agent-usage 相关——模型厂商官方博客与定价页、harness/agent 工具仓库与 changelog、skills/MCP 市场与榜单、tokens 中转与算力平台公告；taxonomy 重构为**模型 / 环境（harness·工具）/ 技能（skills·MCP）/ 算力成本**；prompts 按自有标准改写；gold-selection 100-200 条（A0 纠错样本为首批）；全量换品牌。**其持续维护成本计入 §6.2 单位经济账。**

**v0 验收**：pack 结构落库；AI pack 完成 sources+taxonomy 初稿；manifest 依赖声明示例齐全。

### §4.5 L3 领域技能层

分层：通用技能（66+，已有）→ 角色技能（asp packs）→ 领域技能（从 kb sops/ 编译）。编译流程：SOP（≥3 次验证）→ skill 提炼 → **§4.3 发布回归门** → asp 发版。原则不变：**方法在 skill、事实在底座**。

### §5.1 外部组件选型（工具融合，2026-09-30）

> 完整调研（约 40 仓逐仓核验：星数/许可证原文/最近提交/刷星剔除）见 Notion《工具融合调研·GitHub 现成方案候选清单 v1.0》。本节只存决策，不复制矩阵。

**五原则**：①许可白名单——MIT/Apache-2.0 进代码分发链，AGPL/无许可项目只作外部服务消费其输出（消费 RSS/API 不涉及再分发义务）；②数据边界 P0——本地优先/自托管，云 SaaS 只处理公开层素材，接入前先在 §4.0 矩阵补行；③单一事实源不漂移——git+md 永远是 L2 源，图库/向量库只是可丢弃可重建的索引层；④硬分叉纪律延伸——所有外部件锁版本+薄适配层+可替换路径；⑤时机纪律——A0 零新依赖，每个引入绑定路线图阶段。

**选型结论**：

| 层 | 组件（许可） | 融合方式 | 时机 |
|---|---|---|---|
| L4 | promptfoo（MIT） | §4.3 回归门执行器：gold+held-out 声明式测试集+CI 卡口（与 gold-selection.jsonl 商品形态对齐） | A1 后 PoC |
| L1/L3 | github-mcp-server（MIT） | 每日 PR/分 commit/周审 merge/CI 触发的机制层 | A1 |
| L1 | instructor（MIT） | 结构化抽取库：七字段事实 schema 化输出（抽取用便宜模型，落 md 归我们的管线） | Phase C |
| L0 | crawl4ai（Apache-2.0） | 网页类信源抓取执行器（→LLM 友好 markdown），不改 AIHOT 主干 | Phase B |
| L0 | RSSHub（**AGPL**） | **仅外部服务**：自部署/公共实例的 feed 直接接入信源，代码不进链 | Phase B |
| L2 | graphiti（Apache-2.0） | v1 检索索引层首选：双时态模型与七字段同构（valid_at/invalid_at ↔ pub/ver，失效链 ↔ sup）；md 仍是唯一源，索引可重建；后端 Neo4j/FalkorDB（Kuzu 已弃用） | v1 MCP 检索阶段评估 |
| L4 | mem0（Apache-2.0） | 通道① 会话事实抽取候选；只作会话工作记忆，确认的偏好/纠错仍走 git PR 进 positions | Phase C/D 评估 |

**排除清单（要点）**：AGPL（basic-memory/khoj/honcho）理念再贴近也不进代码链；agent 平台类（letta/MemOS）与「环境而非平台」定位冲突，引入即被运行时绑定；无许可/NOASSERTION（Wechat2RSS/Hyper-Extract 代码部分）默认保留所有权利，仅可作外部服务；langfuse EE 功能不进分发链。星数须 API 复核交叉验证（调研中已剔除 26.9 万星刷星嫌疑仓库）。

**治理层自建清单（＝差异化本体，不外包）**：三层分区与发布门 checklist、七字段 schema 与 90 天复核期、去重规则与 pending 双链、周审 checklist 与审阅预算、compaction（合并+过期降级+sup 链）、SOP→skill 编译规则、回归门留档规范（批准人/版本号/回滚）。

| 风险 | 对策 |
