> **阶段：A0 试验中的周度汇报/候选决策输入；读者：agent。** 本稿回答“外部世界本周有什么变化，具体能使我们的环境少花钱、少返工或多做事？”不是项目困难清单，也不是 PM 行业新闻。用户本轮查看全文只是为了校准周报方向；常规运行只向用户呈报成熟的 C 类拍板项。

> 外部信号窗口：2026-09-26—10-01；核验日：2026-10-01（UTC+08:00）。价格来自本轮实拉的 [OpenRouter 模型 API](https://openrouter.ai/api/v1/models)，是**该通道的当前标价**，不是你的账单。官方文章与 release 直接读回；没有复核的社媒/二手说法不进主表。本轮没有购买、安装、升级或改动仓库。

## 0. 只用来匹配信号的环境基线 C0

- **现有任务**：AIHOT 情报预筛/抽取与周报汇编；AI-cold-start 的 skills、AGENTS 和可选 MCP 维护；跨 agent 代码检索、Notion 协作与质量回归。[SIAE 总控](https://github.com/xjinya-xiangwu/SIAE/blob/27b4f062b86c/README.md)、[规划 §4.2–4.3](https://github.com/xjinya-xiangwu/AIHOT/blob/0cea462fde1e/planning/product-plan-v1.4.md)。
- **已核版本**：SIAE 文档写主力 ZCode/GLM-5.3（非本轮运行遥测）；本机只读命令核得 Claude Code **2.1.233**、Codex CLI **0.159.2**、`rg` **15.2.0**。AI-cold-start 远端已到 [v0.13.0](https://github.com/xjinya-xiangwu/AI-cold-start/commit/57c09e824ea16ee1ed1eeb045ffb61c4a8040b19)，但不能由仓库 HEAD 推断每台设备都安装了它。
- **尚缺**：实际订阅/API 分摊费用、按任务的输入/输出 token 与可采纳结果、各端在用模型映射。因此下文“便宜几倍”仅指**同一通道、同一合成工作量的报价差**；不称实际节省，也不建议立刻替换主力模型。
- **边界**：外部付费服务和新工具不得接触私人层 P、密钥或雇主/客户资料；下面的试验只用有权使用的公开样本。现阶段优先已有标准库、`rg`、现有发布/测试机制，不为新闻添加依赖。

## 1. 外部 Δ → 进化动作卡

### ① 降本：同等可采纳产出花更少

**C-01｜便宜的抽取档有了可比的通道报价，而不是“换整个主力 agent”。** 本轮 [OpenRouter API](https://openrouter.ai/api/v1/models) 返回：`openai/gpt-6-luna` **$0.10/$0.50**、`:batch` **$0.05/$0.25**，`deepseek/deepseek-v4.1-flash` **$0.03/$0.50**，`z-ai/glm-5.3` **$0.2219/$3.39**（依次为每百万输入/输出 token 的美元标价）。Luna 于 09-22 已入目录，DeepSeek 4.1 Flash 更早；**这是本周重新核价所得的可用选项，不冒称本周新发布**。

| 可复算的**合成情景** | GLM-5.3 API | Luna API | Luna batch | DeepSeek 4.1 Flash API |
|---|---:|---:|---:|---:|
| 单次文本任务：100,000 输入 + 10,000 输出 token | $0.05609 | $0.01500 | $0.00750 | $0.00800 |

计算＝输入 token×该通道输入单价＋输出 token×输出单价；**每次请求低于 Luna 272k 输入加价门槛**，不含缓存、web/search、工具调用、税费及重试。该情景只用于比较价目；若现有 ZCode/Claude/Codex 工作在包月额度内，迁到 API **可能反而增加现金支出**。落点仅是未来计量的 L0 预筛/结构化抽取或非实时重跑，不是把写作和高风险评审全部降档。

→ **B 级动作**：以一批公开的真实情报素材对 GLM-5.3／Luna／DeepSeek Flash 做相同 schema 的抽取试验；先验质量，再算“每条被采纳事实的总成本”（含失败重跑），优胜者才进入模型档位建议。没有已开通的 API/预算时只准备数据与报价，不开户、不消费。

**C-02｜本周新模型 Sonnet 5.5：单价不降，效率可能变好。** [Anthropic 09-28 官方指南](https://claude.dev/blog/building-with-claude-sonnet-5-5/)称相对 Sonnet 5 输出速度快约 30%，因用更少 token 完成工作，部分任务成本最多降低 30%；**这是厂商主张，非 SIAE 实测**。其输入/输出每百万 token 仍为 **$2/$10**；OpenRouter [API](https://openrouter.ai/api/v1/models) 列 `anthropic/claude-sonnet-5.5:batch` **$1/$5**。官方迁移指南同时指出默认 thinking 与工具调用等行为变化，旧的 `content[0].text` 读取方式可能失效。

→ **B 级动作**：只选“周报汇编/文档评审”这种可校验任务，同素材比较 Sonnet 5/5.5 的质量、用时、总 token 和调用成本；异步 batch 仅在实际通道与交付时限允许时测试。若当前并未以 API 计费或接入层不兼容，不宣称 30% 降本，不批量切换。

**C-03｜改优化指标。** [OpenRouter 10-01 官方方法](https://openrouter.ai/blog/insights/cost-vs-quality-tradeoff-framework-for-agent-models/)主张先定任务质量下限，再在**自己的样本**上量成本，选择越过质量门槛且有余量的最低成本模型。→ **A 级采纳为实验口径**：价格表只作候选筛；正式比较用 `总费用 / 人工确认可采纳的任务数`，而不是“每百万 token 最便宜”。不引入新服务，仅借鉴判断方法。

### ② 增效：同等投入少返工、少查找

**E-01｜Claude Code v2.1.286 修复了本机旧版本会遇到的风险面。** [09-30 官方 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.286)明确修复 `--resume`/`--continue` 在并行工具调用后崩溃可能丢失轮次，以及若干 MCP 错误消息/日志暴露凭据的情形。本机实测为 **2.1.233**，所以版本差成立；但**未在本机复现或验证修复**。

→ **B 级动作**：先在隔离配置/可回滚副本做两个回归场景（并行工具调用后恢复会话；模拟不含真凭证的 MCP 错误脱敏），留旧版/新版结果与配置备份；通过才提实际环境升级。不要把发布说明当作“已经修好我们的问题”，也不要一次升级所有端。

**E-02｜工具“连得上”不等于“用得对”。** [OpenRouter 09-30 官方教程](https://openrouter.ai/blog/tutorials/how-to-test-tool-calling-accuracy-in-ai-agents/)把工具选择、参数 schema 与执行轨迹分别测量。SIAE 的 `asp doctor` 已验证 MCP 握手，但这尚不能证明 agent 在真实 Notion/仓库任务中会选择正确工具、传正确参数。

→ **B 级动作**：用 5–10 个**只读**任务建一张跨 agent 能力卡（应调用哪个工具、参数应为何、是否错误调用、是否泄露数据）；先测现有连接，再决定是否增加 MCP 或修改 skill。结果落 L4 评测集候选，不直接宣称“全端能力拉齐”。

**E-03｜本周上升的 jevgrep：在当前 Windows 环境**不**推荐安装。** [项目 README](https://github.com/dzhng/jevgrep)与 [MIT 许可](https://github.com/dzhng/jevgrep/blob/main/LICENSE)可核，但官方明确要求 **macOS/Linux、Node 22+ 和外部模型网关 key**；作者的“约 30% 成本降低”来自 10 个 Python SWE-bench 任务且不含 Jev 费用，并非 SIAE 收益。本机已有 `rg 15.2.0`。

→ **拒收本周安装/入包提案**；保持 `rg` 和直接读文件。若将来有 Linux 沙箱且跨文件语义检索成为反复出现的真瓶颈，先测数据外发边界和 `成本/完成任务`，再决定是否试用。拒收理由回流传感器，而不是把 GitHub 星数等同于适用性。

### ③ 进化：让 agent 获得原本做不稳的能力

**V-01｜官方 eval 构建与 hillclimb 方法可用于“自进化”，前提是保留未见过的测试集。** [Anthropic 09-28 官方文章](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)推出 `claude-api` skill 的 `/claude-api build-eval`、`hillclimb` 指导：贴近真实任务取样、先检验 grader、一轮只改一个变量、用 held-out 捕捉过拟合；结果在噪声内就不合并。[该 skill 目录许可为 Apache-2.0](https://github.com/anthropics/skills/blob/main/skills/claude-api/LICENSE.txt)，但它面向 Claude API，不等于通用多 agent 产品能力。

→ **B 级动作**：先复用现有样本与标准库脚本，给“情报筛选→动作落点”做一个小型 train/held-out 对照；分别记录误收、漏收、误桶与动作可采纳性，单轮仅改一项规则。只有多轮真实任务受益且许可/分发核验后，才考虑把方法提炼成 SIAE SOP 或可选 skill；**不在 A0 直接安装全家桶**。

**V-02｜外部自主工作流已从定时扩至事件触发，但本周无需换平台。** [Factory 09-30 官方公告](https://factory.ai/news/automations)称 Automations 已开放，可由日程、GitHub、Slack、webhook 触发，选择模型与执行机器并保留运行记录。这提示 SIAE 将来能把“事件→采集→候选动作→审核”从周一手工发起变为持续感知。

→ **观察/后置 B**：先用已有 SIAE 日志和原生调度能力设计**只读**增量提醒的验收例，不注册新供应商、不连接私有仓库、不授予服务账号。只有 A0 证明有用、现有原生能力不足且安全/费用可接受时，再评估 Factory 或同类平台；这周不拿新闻当上云理由。
