# Phase A0 · 最小闭环试验协议

> 状态：进行中（启动 2026-09-29，批准人：徐劲亚）｜对应 product-plan-v1.1.md §7 A0 行
> 目的：在扩建任何基础设施（Docker/VPS/自动管线）之前，先验证「反馈能否改善下一次任务」与「是否存在真实付费意愿」。

## 1. 试验任务（D12 重构：L0→L1 内容机制试产）

**Agent 使用情报周报**：每周一份『此刻该把 agent 换成什么、装什么、迁去哪』——新模型发布/降价、新 harness、能更好完成某任务的新 skills/插件/MCP、新的便宜 tokens 中转站与算力平台；**每条落到一个可执行动作**；**剔除与 agent 使用无 immediate 关系的一切内容**（资讯本身不是刚需，用户不缺信息渠道）。交付物 = 1 页 markdown。

现用替代方案（用户现状）：手动刷模型榜 / GitHub trending / 多渠道拼凑，且没有"该不该换、值不值得迁"的判断层。
收益假设（L1 pack 维护者视角）：每周产出一份可执行的 pack 更新清单（新技能入包候选 / 模型推荐档位调整 / MCP 清单 / 成本参数），维护工时 ~3h/周 → <0.5h/周；关键更替不遗漏。

## 3. 盲评设计

- **基线**：未装知识底座的同一 agent 产出（即 S2 的 v0）。
- **评审人**：专家本人（知道 v0/v1 但不知哪份对应哪个版本的编号打乱）。
- **四项指标**：①交付物可采纳率（条目可直接用于工作的比例）②证据错引率 ③应拒答/限定表述时的表现 ④完成时间。
- **go 门槛**：v1 可采纳率相对提升 ≥20% 且错引率不升。
- **no-go**：未达标 → 修订假设重跑一次；再不达标 → 暂停 B/C/D 扩建（见 plan §7）。

## 4. 付费意向验证（并行）

在私域/闲鱼挂预售，**预售对象 = L1 技能包（Agent 执行环境，asp base + ai-pm 体系）**而非简报——简报只是 L0→L1 的内容更新机制（D12）：门槛 = ≥1 个真实付费行为（预付/定金）。口头兴趣不计入。

## 5. 数据边界（强制，见 plan §4.0）

- 本试验全部素材为公开网页信息（仅链接+自写摘要）；专家纠错批注中若涉及私人内容，批注原文存 `kb/ai/private/`，仅提炼后的通用规则进工作层。
- 简报中不出现任何在职/前任雇主与客户材料。
- gold 样本（该收/不该收判定）仅含公开素材判断，可进商品层候选。
