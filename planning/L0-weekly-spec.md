# L0 周报规格 v2.2 —— 从「环境进化/降本增效」倒推的采集定义

> 2026-10-01 定稿；同日 v2.1 修订：**读者分离与周会循环**（见 §六）｜ 隶属 L0 内容策略（与 L0-content-strategy.md 互补）
> 定位重述（D12 + v2.1）：周报不是新闻产品，是 **agent 的自进化作业输入**——agent 读周报 → 得出改进动作 → 自动执行无需拍板的部分 → 把需要拍板的整理成「决策简报」向用户（老板）汇报 → 拿到反馈回写。用户唯一感知面 = 决策简报。

## 一、目标倒推链

```
总目标：agent 运行环境持续进化、降本增效
  ↓ 分解
① 降本    = 同等产出花更少 → 必须知道【现在花多少、花在哪】×【价格/通道变化】
② 增效    = 同等投入产更多 → 必须知道【任务怎么做】×【方法/技能/工具变化】
③ 进化    = 能力边界扩张   → 必须知道【现在缺什么】×【生态新能力】
  ↓ 共同前提
环境自状态（baseline）——不知道基线，一切外部信号都无法变成动作
  ↓ 因此
周报 = f(环境基线, 外部世界 Δ) → 进化动作清单（每条带落点组件与预期收益）
```

**第一性结论：周报的第一个采集对象是我们自己的环境，其次才是外部世界。**

## 二、六个采集项（按目标倒推，非按信源分类）

| # | 采集项 | 服务目标 | 采集内容 | 主信源 | 产出动作类型 |
|---|---|---|---|---|---|
| C0 | **环境自状态** | 全部（基线） | 在用模型×任务映射、月成本画像、栈版本（harness/MCP/skills 清单）、已知痛点 | aihot 回执/各端 usage 统计、asp 清单、人工补 | ——（其余各项的分母） |
| C1 | **成本雷达** | 降本 | 仅盯 C0 在用模型/通道的价格 Δ、更廉价替代、batch/缓存价、中转与本地推理性价比 | OpenRouter 价格与用量榜、厂商定价页、aihot 精选（价格类）、linux.do（中转） | 改模型档位 / 切通道 / 开 batch |
| C2 | **任务-模型审计** | 降本+增效 | 每个任务原型（抽取/写作/评审/代码检索/评测…）的当前模型是否仍是最优成本-质量点 | Arena/AA 榜单变化（经 aihot）、C1 数据 | 档位表逐格复核 |
| C3 | **技能生态 diff** | 增效+进化 | 新 skill / 重要更新 / **淘汰信号**（功能被 harness/MCP 原生吞掉）；license 白名单过滤 | GitHub 新星（三路检索）、awesome 清单、skills.sh、asp collector | 装 / 升级 / 移除（入 asp packs） |
| C4 | **harness 能力变更** | 增效+进化 | 只有影响工作流的：新能力、可靠性关键修复、「X 现在内置→Y 可移除」 | 四家 release 正文（Claude Code/opencode/codex/gemini-cli）+ 国内端 | 升级 + 依赖瘦身 |
| C5 | **方法与算力基建** | 进化 | 质量工程实践（→SOP 候选）；自托管/算力新选项（仅当优于当前通道） | aihot tip/paper 类精选 | SOP 采纳 / 算力迁移评估 |

## 三、产出格式（v3 起执行）

1. **环境基线快照**（C0）：在用栈 + 成本画像 + 数据缺口标注（缺口本身是待办）
2. **进化动作清单**（按 降本/增效/进化 三类，每条：动作 + 落点组件 + 预期收益（量化或标注估算）+ 验证方式）
3. **成本雷达**（C1）：在用模型价格表 Δ + 替代通道对比
4. **任务-模型映射审计**（C2）：任务原型 → 当前 → 建议 → 依据
5. **技能 diff**（C3）：新增候选 / 更新 / 淘汰候选（license 标注）
6. **harness 变更**（C4，只留影响工作流的）
7. **方法采纳**（C5 → SOP 候选，进 L2 通道）
8. **不采纳清单**：看过且拒的 + 一句理由——**这直接是 L0 传感器的 gold 负样本**（校准闭环）

## 四、采集纪律（继承+新增）

- 继承：agent-usage 一票否决；license 白名单（MIT/Apache 可装，AGPL/无许可仅信源）；§4.0 数据边界
- 新增：**没有落点的情报不收**——每条必须有「改什么组件」的答案，否则进不采纳清单
- 新增：**量化优先**——价格用 API 实拉（OpenRouter /api/v1/models），不转述二手比价文
- 新增：基线数据缺口如实标注，不编造成本数字

## 五、与架构的咬合

- 动作清单 = §4.2 管线的「①入包项」草案（人审后进 asp 周更）
- 不采纳清单 = 传感器 gold 负样本（季度校准 §4.3）
- 方法采纳节 = L2 sops/ 候选输入
- 长期：本规格的采集项即 AIHOT 实例的信源与 prompts 配置需求（Phase B 落地时对齐 domain-pack sources.json）

## 六、读者分离与周会循环（v2.1 历史设计；现行输出形态见 §七）

**原则：周报给 agent 看，用户只看决策简报。** 类比每周自进化周会：agent 是员工（准备材料、执行决议），用户是老板（只拍板）。

**两个产物**：
1. **周报（agent 版）** `deliverables/YYYY-MM-DD-agent-env-weekly-vN.md`——全量：基线/diff/动作清单/负样本。读者是 agent，格式为机器友好结构化文本。
2. **决策简报（老板版）** `deliverables/YYYY-MM-DD-decision-brief-#N.md`——一页纸，只含需拍板项。用户唯一感知面。Notion 同步为主版（用户习惯面），repo 存档为审计链。

**动作三级分类（周报中每条动作必标）**：
- **A 自动执行**：无外部影响、可回滚、不花钱——agent 直接做，周报记「已排程」
- **B 评估后建议**：agent 先跑测试/评估，产出数据进下期简报——不直接做
- **C 需拍板**：花钱/开账号/商业内容/身份口径/不可逆——进决策简报

**周会循环（每周节拍）**：
```
周中：agent 按上期周报执行 A 类、跑 B 类评估
周末/周一：新周报产出（含「上周决议复盘」节：C 类拍板结果 + A 类执行结果 + B 类评估数据）
        ↓
决策简报（新增 C 类 + B 类升级来的请示项）→ 用户拍板
        ↓
决议回写：broadcast log 记录（decision 类条目）→ 下期复盘引用
```

**决策简报格式（老板版铁律）**：每项 = 事项一句话 + 建议（agent 明确立场）+ 影响（金额/时间/风险，量化或标注估算）+ 你需要做的（勾选级简单动作）。全表 ≤7 项——超过说明 agent 在向老板甩锅，该自己做掉。

## 七、2026-10-01 输出形态修订（v2.2，现行）

**本节覆盖 §六的“两个产物/独立决策简报”默认形态，但保留 A/B/C 权限分级与决议回写纪律。** 用户确认把 Agent 周报与 skills/模型候选选择表合为**一份文档**：[统一模板](templates/agent-evolution-weekly.md)，按[执行指南](agent-weekly-guideline.md)填充；[本期合并样例](deliverables/2026-10-01-agent-evolution-weekly-merged.md)仅作样例，不复制其价格/榜分到未来周报。Notion 是人类阅读/选择面，GitHub 模板与指南为单一事实源。

- **Agent 工作区**：同一文档前半保留 C0 环境基线、外部 Δ、价目与实验口径、进化动作、拒收/沉淀；每条须有原始出处、时间、当前任务与落点组件。项目状态不能代替外部输入。无 C0 实际成本时只能提供可复算情景价，不能称本环境已经降本。
- **用户选择区**：同一文档的 skills/项目热榜、模型能力榜各有 `试评/观察/不考虑` 待填栏，榜单后给 Agent 明确建议。用户可按 ID 回复；未回复默认为观察。**试评只入评测池**，不是安装、购买、接入私人材料或上架授权；高风险 C 项在同页另列短卡，仍需明确拍板。
- **榜单口径**：周榜、24h 榜、当前累计安装量、当前 star、模型基准能力分与通道价格必须分列并标来源/采集时间。skills.sh `/trending` 页面 UI 为 24h，不得用其 SEO 标题宣称七日增长；没有逐日留存快照时不编造周增量。模型榜必须固定 exact ID + effort/fallback，独立基准不等于本项目任务成绩。
- **建议与知识门**：热度只是发现；先筛许可、OS、密钥/外发、既有功能重复，再在获授权样本上测质量/成本/安全。只有实测通过且人审发布门满足时可晋升 L1，实际使用/专家纠错才进 L2，误收/拒收回流 L0/L4。每期先复盘上一期用户选择与试评结果，不能仅换一批榜单重写文章。
- **PM 产品版**：面向付费 PM 用户的行业情报杂志是独立人格/商品输出，不能混入 SIAE 内部自进化周报；旧 `pm-weekly` 样例保留历史。
